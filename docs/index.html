Check the worker runtime

Preflight runs once. The Codex CLI must be installed and authenticated.

Preflight · shell
command -v codex && test -f ~/.codex/auth.json

If preflight fails, stop and report the missing installation or authentication. Sign in with codex login.

Launch a worker.
Keep the boundary.

One brief in. One report out. Launch each slice as a background task and wait for completion notifications.

Already running gpt-6.1-sol at high reasoning in Codex? Use the host’s own subagents and skip this shell call.

Worker launch · shell
codex exec -m gpt-6.1-sol -c model_reasoning_effort=high -c service_tier=fast \
  -s workspace-write --skip-git-repo-check -C "<repo>" \
  -o "<scratch>/<slice>.out.md" - < "<scratch>/<slice>.brief.md"

Replace <repo>, <scratch>, and <slice> with your repository, scratch directory, and slice name. The command is reproduced from SKILL.md.

Independent slices

Run in parallel only when they share no files, state, or ordering. Run dependent slices in sequence.

Completion, not polling

Block on completion notifications. Never short-poll the workers.

The brief is
the handoff.

Write one brief per slice to <scratch>/<slice>.brief.md. Make the outcome, owned paths, and acceptance checks explicit.

Brief template · Markdown
Objective: <one outcome>
Owned paths: <only files/dirs this worker may change>
Interfaces to honor: <APIs, types, contracts that must not change>
Constraints: <repo rules, no git push/merge, no store uploads>
Acceptance: <exact commands/checks that must pass>
Known facts: <verified findings, file:line>
Report once at the end: changed files, checks run with results, open problems. No progress messages.

Delegated work.
Retained responsibility.

The orchestrator owns integration, verification, and authorized delivery.

  • Keep the sandbox

    Keep -s workspace-write. Never use --dangerously-bypass-approvals-and-sandbox.

  • Keep delivery authorized

    Workers never commit to main, push, merge, or publish. The orchestrator does that only when authorized.

  • Use actual Sol workers

    Never use a Claude/Opus subagent as a Sol stand-in.

  • Verify the result yourself

    Read each .out.md, confirm git diff --stat touches only owned paths, then run acceptance checks yourself. A failed slice gets one re-brief with evidence; report a second failure.

Done means checked.

Every slice’s acceptance checks pass under your own run, or the failing slice is reported with its evidence and what remains.
